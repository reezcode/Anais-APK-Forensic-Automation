# Reema Agent

Reema is the **static** half of Anais: intake, enrichment, static analysis, a
capability-and-verdict engine, IOCs, and the **Vaccine Pack**. Use it whenever a
claim depends on what a local Android (or iOS) app package *contains* — not what
it does at runtime. Running an app on a device is **Dyxon** (`dyxon-agent`);
deep native/managed recovery is **REA**.

This skill is host-neutral. Prefer the MCP tools when the Anais MCP server is
connected; otherwise use the `python3 -m reema` CLI — the same pipeline either
way.

## Route the request

1. **Static facts about an APK/JAR/IPA** (permissions, SAST, RASP/packer,
   obfuscation, framework, signing, SDK/tracker inventory, DEX/encrypted-payload,
   IOCs, composite risk, malice-vs-posture verdict): run the **static pipeline**.
2. **What capability did it use, and how do I defend against it** (SOC/IR triage,
   "virus → vaccine"): read the **Vaccine Pack** (`reports/vaccine.json` +
   `reports/vaccine/*.md`), auto-generated by every analyze run.
3. **Native/managed logic the static pass can't see** (Flutter Dart, Unity
   IL2CPP, Xamarin IL, stripped `.so`, a RASP abort path): run analyze, then
   execute the **REA deep tasks** and merge them.
4. **Runtime confirmation / run it on a device**: that is dynamic — hand off to
   the **`dyxon-agent`** skill. Reema does not execute the app.

## How to run it

### Static pipeline (+ optional REA bridge)

- MCP: `anais_analyze({ apkPath, yara?, rea? })` → `workDir`, report paths,
  summary. `rea: true` also runs REA's cheap passes and emits the deep-task list.
- CLI: `python3 -m reema analyze /abs/path/app.apk` (`-y <rules>` for extra YARA,
  `--offline` for cache-only enrichment, `ANAIS_REA=1` to add the REA bridge).
- Outputs land in the case dir: `reports/findings.json` (`reema.findings/v1`),
  `reports/vaccine.json` + `reports/vaccine/`, `reports/report.*`, `case.json`.
- Read results: `anais_read_report({ workDir })` (`full: true` for the whole
  `report.json`), or read `<workDir>/reports/findings.json` /
  `reports/report.md`.

### REA deep pass (agent-driven)

Only when `rea: true` / `ANAIS_REA=1` queued deep questions.

1. `anais_rea_targets({ workDir })` → `rea_targets.json` (schema 2).
2. Execute each task with REA's deep tools (`open_binary`/`trace_native_values`
   for native + RASP abort paths, `inspect_il2cpp_metadata` for Unity,
   `inspect_managed_artifact` for Xamarin, `open_binary` on `libapp.so` for
   Flutter). Keep every Evidence record; never assert beyond what REA returns.
3. `anais_merge_deep({ workDir, results })` → writes `rea_deep.json`, regenerates
   the report's Deep Pass section, compiles `frida_auto.js`. See
   `references/rea-deep-pass.md`.

## Reading the verdict

`findings.json` separates **malice** (evidence of intent) from **posture** (build
weaknesses) and **context** — ADR 0002. Each finding has `owner` (`app` vs
`sdk:<name>`): **start triage from `summary.malice_by_owner.app`**, not raw
counts (SDK noise is downgraded). `verdict` is malicious / suspicious / pua /
clean; `family` merges chain/enrichment/YARA family signals.

## The Vaccine Pack

For each capability Reema found, `vaccine.json` carries a **defense** (controls),
a **check**, and optionally a **harness** reference. It is the contract Dyxon
consumes to test an app on a device. Harness *content* for real capabilities is
backlog B14; the engine ships one neutral example.
